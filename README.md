# Repo handoff

This repository is a static GitHub Pages-style site with a custom post index and post renderer.
There is no package manager setup in the repo root right now, and post metadata is generated by a small Node script.

## Repo map

- `_posts/`: markdown posts that are published on the site.
- `_posts/old/`: archived posts that are still indexed and still load through `post.html`.
- `scripts/update_posts.js`: scans `_posts/`, reads front matter, and regenerates `assets/data/posts.json`.
- `assets/data/posts.json`: generated metadata file used by the homepage and post loader.
- `index.html`: homepage that reads `posts.json` and lists posts.
- `post.html`: post page that loads a post by `id`, fetches markdown, and renders it.
- `.nojekyll`: important for publishing underscore-prefixed folders like `_posts/` directly.

## How posts work

The current live post ID is the markdown filename without `.md`.
That ID is written into `assets/data/posts.json`, and the post URL becomes:

```text
/post.html?id=<post-id>
```

`post.html` first looks up the post in `posts.json`, then fetches the markdown file from `/_posts/<path>`.
Because of that, renaming a post file changes its ID and URL.

## Filename rule

Active root posts now use this filename format:

```text
YYMMDDNNNN.md
```

- `YYMMDD`: date prefix
- `NNNN`: sequence number for that date, starting at `0001`

For posts on the same day, the site orders them by `NNNN` ascending.

Examples:

```text
2605030001.md
2605030002.md
2605030003.md
```

Archived files in `_posts/old/` still use older names and are intentionally left as-is.

## How to write a post

Create new posts inside `_posts/`.
Keep front matter simple and explicit.
Use this shape unless a post really needs more:

```yaml
---
layout: post
title: Your title
date: 2026-05-03 00:00:00 +0900
---
```

Important notes:

- Always set `date:` explicitly.
- Do not rely on the filename alone for the post date.
- Keep front matter single-line where possible.
- The parser in `scripts/update_posts.js` is intentionally simple.
- Markdown files whose filename starts with `!` are ignored by the generator.

## How to publish post metadata

After adding, removing, renaming, or editing posts, regenerate `posts.json` from the repo root:

```powershell
node scripts/update_posts.js
```

Do not hand-edit `assets/data/posts.json`.
That file is generated output.

## How date extraction works

`scripts/update_posts.js` currently resolves the post date in this order:

1. `date` from front matter
2. `YYMMDDNNNN` filename prefix
3. legacy `YYYY-MM-DD-*` filename prefix

For numeric filenames, explicit front matter is still the safest option and should be treated as required.

## Preview workflow

Do not preview the site through `file://`.
`index.html` and `post.html` use `fetch`, so they need an HTTP server.

Simple local preview options:

```powershell
python -m http.server 8000
```

Then open:

```text
http://localhost:8000/index.html
http://localhost:8000/post.html?id=2605030001
```

## LLM notes

- Work only in the real repo, not a copy.
- Do not edit `assets/data/posts.json` by hand.
- If you rename a post, expect its public `id` and URL to change.
- `_posts/old/` is still part of the generated index.
- Keep edits minimal and consistent with the existing site style.
- If a post uses embedded HTML or iframe content, preserve it exactly unless the user explicitly asks to change it.
