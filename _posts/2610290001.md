[KAIST Mobility Group](https://kaistmobilitygroup.com/) 홈페이지에 들어가면 맨 위에 큰 사진 슬라이더가 있다.
화살표를 누르면 사진이 그냥 페이드되는 게 아니라 잘게 쪼개진 조각처럼 옆으로 밀리면서 다음 사진으로 넘어가고 제목 글자는 가운데부터 하나씩 튕겨 나갔다가 다시 튀어 들어온다.
볼 때마다 저거 어떻게 한 건지 궁금했는데, 이번에 뜯어보고 블로그에 그대로 옮겨왔다.

일단 결과물부터.
화살표를 눌러도 되고 사진을 옆으로 끌어도 된다. 가만히 두면 20초마다 알아서 넘어간다.
사진은 포트폴리오에 올려둔 중경삼림 스틸컷을 그대로 썼다.

## 원본은 뭘로 만들었나

페이지 소스를 열어보면 WordPress에 `blackdsn`이라는 유료 테마가 깔려 있다.
슬라이더 위젯 이름은 `dsn_slider_project_three`다. 마크업에는 이런 속성이 붙어 있다.

```html
<div class="main-slider ... dsn-webgl"
  data-dsn-option='{"direction":"horizontal","autoplay":{"delay":20000}, ...}'
  data-dsn-webgl='{"displacement":".../displacement/1.jpg","intensity":-2,"speed_in":1,"speed_out":1.2}'>
```

눈여겨볼 건 `dsn-webgl` 클래스다.
테마 JS(`custom.js`, `dsn-grid.min.js`)를 받아서 읽어보니 구조가 대충 이렇다.

- 슬라이드 자체는 Swiper가 관리한다. 근데 진짜 사진은 Swiper가 안 보여준다. Swiper 컨테이너는 `opacity: 0`으로 숨겨두고 순서만 센다.
- 사진은 Three.js로 그린 WebGL 캔버스 한 장에서 나온다. 화면 꽉 찬 평면 하나에 셰이더를 씌워 두 장의 사진을 섞는다.
- 제목 글자는 Splitting.js로 한 글자씩 `<span>`으로 쪼갠 다음 GSAP 타임라인으로 움직인다.
- 아래쪽 "다음 슬라이드 제목" 라벨은 Swiper 두 개를 더 띄워서 `parallax` 옵션으로 글자마다 다른 속도로 미끄러지게 한다.

라이브러리만 다섯 개다. jQuery, Swiper, Three.js, GSAP, Splitting.
블로그 글 하나에 이걸 다 끌고 올 수는 없어서 동작은 똑같이 두고 의존성 없이 순수 HTML/CSS/JS로 다시 짰다.
WebGL은 브라우저에 원래 있으니까 Three.js 없이 직접 붙였다.

## 사진 전환: displacement 셰이더

이 슬라이더에서 제일 눈에 띄는 게 이 부분이다.
`dsn-grid.min.js` 안에 `WebGLDistortionHoverEffects`라는 모듈이 있다. 거기서 쓰는 프래그먼트 셰이더가 이거다(가로 방향 기준).

```glsl
vec2 uv = (vUv - vec2(0.5)) * resolution.zw + vec2(0.5);
vec4 d = texture2D(disp, uv);

vec2 distortedPosition  = vec2(uv.x + dispFactor * (d.r * effectFactor), uv.y);
vec2 distortedPosition2 = vec2(uv.x - (1.0 - dispFactor) * (d.r * effectFactor), uv.y);

vec4 t1 = texture2D(texture1, distortedPosition);
vec4 t2 = texture2D(texture2, distortedPosition2);
gl_FragColor = mix(t1, t2, dispFactor);
```

생각보다 단순하다.
`disp`는 흑백 텍스처다. 픽셀마다 밝기(`d.r`)만큼 사진을 x축으로 밀어버린다.
`dispFactor`가 0에서 1로 가는 동안 나가는 사진은 점점 더 많이 밀리고 들어오는 사진은 반대쪽에서 밀려 있다가 제자리로 돌아온다.
그 사이에 `mix`로 두 장을 섞으니까, 중간쯤엔 두 사진이 조각조각 엇갈린 상태가 된다.

`effectFactor`는 설정에 있던 `intensity: -2`에서 나온다.
방향에 따라 부호를 뒤집어서 다음으로 갈 때와 이전으로 갈 때 밀리는 방향이 반대가 된다.
2면 꽤 큰 값이다. 밝기 0.5짜리 픽셀이 화면 폭만큼 밀린다는 뜻이라 전환 초반엔 원래 사진이 거의 알아볼 수 없게 찢어진다. 원본도 그렇다.

첫 줄의 `resolution.zw`는 CSS `object-fit: cover`를 셰이더로 흉내 내는 값이다.
캔버스 비율과 사진 비율을 비교해서 남는 쪽을 잘라낸다.

```js
const imageAspect = image.naturalHeight / image.naturalWidth
const cover = height / width > imageAspect
  ? [(width / height) * imageAspect, 1]
  : [1, height / width / imageAspect]
```

시간 곡선도 원본 값을 그대로 가져왔다.
데이터 속성엔 `speed_in: 1`이라고 적혀 있는데 테마 코드는 `speedIn`(카멜케이스)을 읽는다. 그래서 이 값은 실제로는 무시되고 기본값 1.6초가 쓰인다.
이징은 `Expo.easeOut`이다. 처음에 확 찢어졌다가 천천히 정리되는 느낌이 여기서 나온다.
GSAP 없이 `requestAnimationFrame`으로 직접 돌렸다. expo out은 한 줄이면 된다.

```js
const expoOut = p => (p === 1 ? 1 : 1 - 2 ** (-10 * p))
```

### displacement 텍스처

원본은 `displacement/1.jpg`라는 527×336짜리 이미지를 쓴다.
열어보면 정사각형 격자를 대각선으로 쪼갠 삼각형 모자이크인데 삼각형마다 회색 값이 랜덤이다.
사진이 "조각나서" 밀리는 느낌은 전부 이 텍스처 덕이다. 노이즈가 부드러우면 물결처럼 휘고 이렇게 각진 조각이면 유리 깨지듯 쪼개진다.

남의 테마 파일을 그대로 가져오긴 좀 그래서 캔버스로 비슷한 걸 직접 그렸다.
원본 밝기 분포를 재보니 평균이 115/255 정도였고 중간 회색이 대부분, 아주 밝은 조각이 드문드문 섞여 있었다.
48×30 격자에 셀마다 대각선 방향을 랜덤으로 고르고 회색 값은 그 분포에 맞춰 뽑았다.
시드를 고정한 난수를 써서 새로고침해도 같은 무늬가 나온다.

### WebGL 붙이기

Three.js가 해주던 일은 사실 몇 개 안 된다.
화면을 덮는 사각형 하나(삼각형 두 개), 텍스처 네 장(사진 세 장과 displacement), 유니폼 몇 개.
정점 셰이더는 카메라 계산 없이 클립 좌표를 바로 쓴다.

```glsl
attribute vec2 position;
varying vec2 vUv;
void main() {
  vUv = position * 0.5 + 0.5;
  gl_Position = vec4(position, 0.0, 1.0);
}
```

나머지는 `gl.createTexture()`로 사진을 올리고 프레임마다 `dispFactor`만 바꿔서 `drawArrays` 한 번 부르는 게 전부다.
레티나에서 흐려지지 않게 캔버스 픽셀 크기는 `devicePixelRatio`를 곱해서 잡았다.
WebGL을 못 쓰는 환경에서는 그냥 `<img>` 세 장을 크로스페이드하는 쪽으로 빠진다.

## 제목 글자 애니메이션

원본 `custom.js`의 `slideChange` 핸들러에 GSAP 설정이 그대로 들어 있다.

```js
show: { autoAlpha: 1, y: 0, rotation: 0, scale: 1,
        stagger: { amount: 0.3, from: "center" }, ease: "back.out(4)" },
hide: { autoAlpha: 0, y: "-25%", rotation: 8, scale: 1.1,
        stagger: { amount: 0.3, from: "center" }, ease: "back.in(4)" }
```

나가는 제목은 0.4초 동안 `hide` 상태로, 들어오는 제목은 0.8초 동안 `show` 상태로 간다.
`from: "center"`라서 가운데 글자가 제일 먼저 움직이고 양 끝 글자가 0.3초 늦게 따라간다.
`back.in(4)`, `back.out(4)`는 오버슈트가 큰 이징이라 글자가 살짝 반대로 움찔했다가 튕겨 나간다. 통통 튀는 느낌이 여기서 난다.

이걸 GSAP 없이 하려면 세 가지가 필요했다.

글자 쪼개기는 Splitting.js 대신 텍스트 노드를 돌면서 단어는 `.word`, 글자는 `.char`로 감쌌다.
`<br>` 같은 태그는 건드리지 않고 그대로 둔다.

stagger 지연은 가운데에서 떨어진 거리에 비례한다.

```js
function centerStagger(count, amount) {
  const middle = (count - 1) / 2
  return Array.from({ length: count }, (_, i) =>
    middle === 0 ? 0 : (Math.abs(i - middle) / middle) * amount)
}
```

back 이징은 GSAP 공식을 그대로 옮겼다.

```js
backIn:  s => p => p * p * ((s + 1) * p - s)
backOut: s => p => { const q = p - 1; return q * q * ((s + 1) * q + s) + 1 }
```

타임라인 순서도 원본을 따랐다.
옛 제목 숨기기가 끝나는 순간 슬라이드의 `dsn-active` 클래스를 바꾸고 그다음에 새 제목이 들어온다.
설명 문단은 JS가 아니라 CSS transition이다. `dsn-active-animate` 클래스가 빠지면 `opacity: 0`, `translateY(50%)`가 된다. 다시 붙으면 1.2초 동안 `cubic-bezier(0.19, 1, 0.22, 1)`로 올라온다.

맞게 만들었는지는 눈대중 말고 숫자로 확인했다.
원본 페이지와 내 페이지에서 각각 다음 버튼을 누르고 `requestAnimationFrame`마다 첫 글자와 가운데 글자의 opacity를 찍어봤다.
가운데 글자는 둘 다 약 340ms에 사라지기 시작하고 첫 글자는 640~700ms 사이에 사라진다. 새 제목의 가운데 글자는 둘 다 710~770ms쯤 나타나서 860~920ms에 다 올라온다.
프레임 하나(60~70ms) 안쪽으로 맞았다.

## 아래쪽 내비게이션

하단 바 왼쪽엔 이전 슬라이드 제목, 오른쪽엔 다음 슬라이드 제목이 원 안의 화살표와 같이 붙어 있다.
넘길 때 이 라벨도 글자마다 다른 속도로 위아래로 빠진다.

원본은 이걸 Swiper `parallax`로 처리하는데, 테마 코드가 글자마다 값을 이렇게 박는다.

```js
$item.setAttribute('data-swiper-parallax-y', `${(index + 5) * 9}%`)
$item.setAttribute('data-swiper-parallax-duration', (index + 5) * 100)
```

n번째 글자는 `(n + 5) × 9%`만큼, `(n + 5) × 100ms` 동안 움직인다는 뜻이다.
뒤쪽 글자일수록 더 멀리, 더 느리게 가니까 단어가 앞에서부터 차르르 풀리는 것처럼 보인다.
이 값을 그대로 쓰되 Swiper 대신 슬라이드별 진행도(-1, 0, 1)에 곱해서 CSS transform과 transition-duration으로 넣었다.
라벨 슬라이드끼리는 Swiper `fade` 효과처럼 CSS grid 한 칸에 겹쳐 두고 opacity만 바꾼다.

가운데 `01 / 3` 숫자도 원본 CSS를 따랐다.
`transform: scaleX(1.5)`로 옆으로 늘리고 `clip-path: inset(0 0 0 20%)`로 왼쪽을 잘라낸다. "0"이 반쯤 잘려서 이상해 보이는 건 버그가 아니라 원래 디자인이다.
원 안 화살표도 같은 방식으로 `clip-path`로 원의 한쪽을 잘라놨다.

## 레이아웃

원본 페이지에서 `getComputedStyle`로 값을 하나씩 뽑아서 맞췄다.

- 슬라이더 안쪽 여백은 위아래 90px, 양옆 100px(태블릿 40px, 모바일 0). 사진은 그 안쪽에 들어간다.
- 화면 아래 절반엔 검정에서 회색으로 가는 그라디언트를 깔았다. 사진 하단은 `box-shadow: 1px 0 31px 45px #101010`으로 뭉갠다. 그래서 사진이 아래쪽 검은 띠로 자연스럽게 녹아든다.
- 제목은 Excon 500, 95px, oblique. 원본이 쓰는 폰트가 Fontshare 무료 폰트라 그대로 불러왔다.
- 992px 이상에서는 화면 가운데에 지름 70vw짜리 아주 희미한 원 테두리가 하나 떠 있다. `opacity: 0.25`에 테두리 색이 `#ffffff0a`라 거의 안 보이는데, 없으면 허전하다.
- 사진 위에 슬라이드마다 다른 검정 오버레이(20%, 50%)를 씌운다. 원본의 `data-overlay` 값을 그대로 따랐다.

블로그 본문 폭이 좁아서 데모는 iframe으로 넣었다. iframe 안에서는 높이를 `100vh` 대신 폭에 비례하게 잡았다. 높이는 `postMessage`로 부모 페이지에 알려준다.

## 원본이랑 다른 점

드래그는 원본과 살짝 다르다.
원본은 Swiper 터치 진행도를 그대로 `dispFactor`에 꽂는데, 나는 드래그한 거리를 화면 폭으로 나눠서 썼다. 반 이상 끌거나 빠르게 휙 넘기면 넘어가고 아니면 0.3초 동안 원래대로 돌아간다.
마우스 휠은 가로 스크롤일 때만 반응하게 했다. 원본은 세로 휠도 먹는데, 블로그 글 중간에 박혀 있으면 스크롤하다가 슬라이드가 넘어가 버려서 그건 뺐다.
나머지 시간 값, 이징, 셰이더 수식, 레이아웃 숫자는 원본에서 읽은 그대로다.
